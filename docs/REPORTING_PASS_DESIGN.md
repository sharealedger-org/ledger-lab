# Expanded reporting pass — design and fixture contract

2026-11-13. Owner authorized design, construction and fixture testing. Exploratory reporting, outside the three Phase 1-comparable corpus measurements. Existing `5v` remains the legacy profile; `5v --reportProfile expanded` selects this reporting topology, followed by `5r` spill reduction. No accounting entries are generated or applied.

## Falsifiable claim and execution contract

One sequential read of each declared canonical SJE and posted-ledger partition, k-way merged at Instrument ID, can produce movement, balance and enriched reporting families without holding the population in memory. Inputs must already be monotonically ordered by literal Instrument ID; disorder fails rather than silently re-sorting canonical history. Dimensions join as additional ordered streams. Small reference tables have an enforced aggregate byte limit. Cheapest falsifiers: corrupt a posted amount, disorder a stream, force spills at two rows, and exceed the vendor-state bound.

Ownership: 05 perspectives over committed 02/03 outputs. Stage 1 uses one row of lookahead per input plus current-vendor aggregates/dimensions, capped by `maxVendorRows`; no completed-vendor population set. Vendor/IP dimensions use `instID`, optional `instHolderName`, `instEffectDate`, `instEffectEndDate`; contract dimensions explicitly use `vendor_id,contract_id`, optional `effective_from,effective_to`, with additional attributes retained. Dimension records must be sorted by the same exact vendor key as financial inputs. No automatic identifier normalization or inferred vendor/contract bridge. Missing/overlapping/undated dimension matches are explicit. No source-derived name hash map replaces a GenevaERS ordered entity join.

SJE schema is the existing headerless 39-field Transaction. Ledger schema is the existing 30 named fields (optional trailing empty column). Posting grain: vendor plus SJE fields 9–22 / ledger fields 5–18. Reconcile signed amounts at that full grain, preserving raw periods; feature years use the explicit fiscal contract (`00YY/MM` is an FY label, full calendar `YYYY/MM` uses July rollover). Monthly/annual granularity is never silently mixed. Default basis `period_movements` compares posted period amounts with SJE amounts. Optional separately declared opening-ledger files use `opening_plus_movements`; never sum a succession of closing snapshots and call them movements. Report basis in evidence. No carry-forward/net-income inference.

Sources are snapshotted by resolved physical paths before reading, avoiding symlink publication changes. Source path, kind, record ordinal and SHA-256 streamed during consumption provide provenance. Only final `LDGRYYYY.csv` files are selected; opening/temporary files require explicit selection. `SortedJEInputs.oneRead` prevents merged plus component double reads. Duplicate resolved paths fail. Reporting starts only against committed completed upstream outputs; its standalone orchestrator neither launches nor overlaps posting.

## Output families

- `movement_history.csv`, `balance_history.csv`, `reconciliation.csv`: vendor, full posting dimensions, signed amount/counts, opening amount, delta/status; correct side presence and dimension coverage remain explicit.
- `vendor_activity.csv`: vendor/FY movement types, signed debit/offset totals, negative direct movements, activity periods and gaps; vendor balances remain separate.
- `relationships.csv`: vendor/FY/agency/fund/commodity/contract, direct movement amount/count and share of vendor absolute direct activity; missing contracts explicit, no fabricated balance-at-contract attribution.
- `aim_movements.csv`, `aim_balances.csv`, `aim_combined.csv`: same vendor/FY key and cutoff, membership/eligibility flags; movement-only, balance-only and matched combined inputs. Named `legacy_sign_v1_plus_annual_distinct` reproduces the old movement view's nonnegative-sign selection (including zero offsets) and monthly maxima of agency/class counts. Annual distinct unions and corrected signed-direct PO count/amount are separately named exploratory fields. No future-presence labels embedded. Unattributed IDs are excluded from eligible vendor inference but retained in financial outputs. The VA inference profile requires one source currency per vendor/FY and fails on mixed currencies rather than adding incompatible amounts; financial history/cross-cut keys retain currency dimensions. Multi-currency inference requires a separately declared partitioned feature schema.
- `dimension_attributes.csv`, `reference_attributes.csv`, `coverage.csv`: available attributes, validity bounds and source lineage; effective-date matching is as of fiscal-year end with undated/ambiguous/missing status. Reference descriptions are contemporary lookup descriptions, not invented historical facts.
- `analysis_packets.csv`: selected vendors' individual movements/balances with source file/record, event/rule identity, amount and accounting dimensions; streamed, not buffered history. All vendor summaries remain available without duplicating all details by default.
- `cross_vendor_totals.csv`: movement and balance cuts by fiscal year, agency, fund and account, with sides separate. Vendor contributions are reduced after the canonical pass. Exact distinct contributor counts use one contribution per vendor/cut/side; never sum monthly distinct counts as annual distincts.

## Spill boundary and publication

Cross-vendor partials use a bounded key buffer and flush sorted associative summaries (key, amount, rows, contributor count) to numbered partition files. `5r` reads these only, never canonical inputs; bounded-fan-in multipass merge/reduce uses at most fan-in cursors, records intermediate bytes and merge passes. No open-file array proportional to all spilled chunks. Ordering is deterministic and output independent of buffer/fan-in choices. Signed financial amounts use BigDecimal.

Existing SortEngine streaming merge contracts and the GERS-003 bounded-extract/reduce model are the substrate; a dedicated associative reducer is a reporting prototype, not proof that GenevaERS MR88/sort-exit capability exists. Record that target capability limitation explicitly. Metrics separate extraction and reduction time, input/output rows/bytes, spill rows/bytes/chunks, peak vendor rows/state keys, peak buffer keys, fan-in/pass count, and per-process OS RSS. Reporting has a distinct run directory and completion marker, with failed attempts retained. A reconciliation failure blocks publication and model consumption.

## Fixture acceptance before corpus

Unchanged baseline: 34 CKBViews/TTL/one-read tests passed before implementation. New fixture: multiple vendors/years, expenditure, commitments, revenue at unattributed grain, negative direct reversal, differing calendar/FY periods, a quoted name, two valid contract versions, missing dimensions and reference lookups. Posted balances must be actual post.scala outputs for a connected fixture. Independently expected amounts must match movement, balance, combined and cross-cut outputs. Explicit opening-ledger fixture separately tests opening + movement. Force tiny and large spill capacities and fan-ins; final products must be identical. Corrupt balance and missing side must fail reconciliation; unsorted sources, bad schema/amount/date, duplicate input and oversized vendor/reference state must fail. Test repeat determinism and original legacy profile unchanged. Execute extraction and reduction in distinct JVMs through the Bash wrapper and inspect evidence before claiming fixture verification. Corpus scale and AI predictive benefit remain untested.
