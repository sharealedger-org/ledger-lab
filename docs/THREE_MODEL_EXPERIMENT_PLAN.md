# Three-Model Experiment: Working Plan

Status: **plan with decisions recorded, 2026-11-11, branch `aim-three-model`.** Nothing here has been run. The experiment definition is in [TEST_DESIGN.md](TEST_DESIGN.md) §2 and §5a and [RESEARCH_OBJECTIVES.md](RESEARCH_OBJECTIVES.md) (Part 2). This file does not change that definition; it turns it into ordered work and records the decisions the design leaves open. The owner delegated D1-D7 to the agent on 2026-11-11 ("I have no opinions... your guidance will be accepted on all the points"), so they are the agent's judgment calls, written down with reasons so a human reviewer can challenge them. They are fixed before any real-data run; a change after that is logged as a deviation, with the reason.

## 1. Approvals and boundaries

- **Python is approved by the owner for this experiment (2026-11-11 session): model training and evaluation, post-engine, not timed.** Per AGENTS.md the scope is restated here and again at the top of each script before it is written.
- **Scope of the approval as understood:** verbalization of GL/LDGR records, label and split construction from the committed outputs, fine-tuning and evaluation of Posted-FineTune and IL-FineTune, building and evaluating IL-Native, and writing `data/test_evidence/three_model_experiment_results.csv`.
- **Not in scope:** any posting, CKB, step-up or aggregation that feeds the models. If a model input needs aggregation over the corpus, it is asked "could Scala/`5v` do this?" first and, if yes, goes through the Scala path (AGENTS.md GenevaERS simulation rule). Python reads the committed output files only.
- **Measurement:** not timed. The experiment is outside the measured financial path and contributes nothing to any cost curve. Run time, machine and library versions are recorded only so the run can be repeated.

3. No bare-year or short-form fiscal periods and no row with the wrong field count (the old PO reader defect; the fixed reader gave none in run 3).
4. The same train/test split, label rule and censoring rule are applied to all three models and written to the results file.

| D2 | Verbalization schema (structured record to text). | TEST_DESIGN.md §5a defers it to "when scripts are written". | D4 | Train/test split. | Prevents leakage; the locked 7 windows is not available on PO-derived tests. | Reuse the hold-out already used for AIM3: train FY2010-FY2013, test FY2014-FY2015 (4 walk-forward windows as a stability check). Same split for all three models. |
| D5 | Metrics. | The gap columns need one metric per task. | Survival: C-statistic and the AIM3 permutation test. Forecasting: sMAPE and RMSE, with a naive last-year baseline. Net Income: correct or not. |
| D6 | Form of IL-Native. | "Structured model, no pretrained LLM" can be many things. | A plain structured model on IL-derived features (the AIM3 features are the starting point), so the 2→3 gap isolates the language prior and not a bigger model. |
| D7 | How "cannot answer" is scored. | Posted-FineTune has no vendor field, so survival is not answerable from its substrate. | Report `not_answerable` as a result, not as a score of zero. |
| D8 | Training sample for models 1 and 2 (added 2026-11-11, step 3). | An LDGR text is about 700 characters; the corpus has 10.65M LDGR rows and 6.43M GL keys, so no model is fine-tuned on every record. | **Entity hash sample, fixed seed 42, one fraction for all training years (FY2010-FY2013), target about 20,000 records per substrate** (`sample_fraction`). An entity is the GL key without period and flag (`agency\|nominal_account_id\|fund\|object_id`) or, for LDGR, `ldgrIPID` (the vendor / instrument id, `CKBViews.scala` col 0). An entity is kept in every year or in none, and both lines of an LDGR event stay together. Same rule, seed and years for both substrates; GL rows carry no instrument id, so the substrates cannot share source events. The achieved record count is written to the results file. | D9 | Net Income ground truth (**PROPOSED 2026-11-11, awaiting the owner**). | The task is the experiment's closing argument (TEST_DESIGN.md §2: Net Income is a chart-of-accounts classification, not a fact in the events). The Gold GL and LDGR have no revenue accounts: in all 14 years the nominal accounts are `EXP*` (payment source), `COMMIT` (PO source, FY2009 has none) and the `0000` offset. A revenue-minus-expense net income cannot be derived from them. | **Net expenditure for agency a in fiscal year t = the sum of `D`-line amounts on `EXP*` accounts**, with `COMMIT` debits excluded as encumbrances (not expense) and the `0000` offset excluded. IL-Native computes it by the posting rule (the chart of accounts); ground truth is the same sum, which is already shown to equal the `GL` total and the `LDGR` total exactly (audit register, 2026-11-11, EXP basis). ## 8. Later paper candidate: statement tie-out (owner direction, 2026-11-12; not decided, not run)

**Problem.** The audited financial statements are the gold standard. A user who queries the subledger by PO or vendor wants the result to tie to a number in those statements. Adjustments that carry no vendor (aggregates, allocations, currency effects) always exist. Fragmented ledger systems can only show vendor detail and a statement total as separate figures; any difference is computed, not explained.

**Pass condition.** For a statement figure S (for example total expenditure for a fund and fiscal year): `S = Σ vendor/PO lines + Σ named adjustment lines`. The "other" part must be built from adjustment records that carry rule identity, source and effective date. It must not be `S − Σ vendor lines`. A result that needs a computed plug fails.

**Why it fits this repo.** The register already requires manual adjustments to be "instrument-anchored or explicitly suspense-anchored", and specifies a residual-reporting view that does not plug (`VERIFICATION_AUDIT_REGISTER.md`, top table). GL and LDGR `EXP` totals already agree in 14 of 14 years (internal tie-out). Non-vendor content exists in the corpus: `Payroll` and aggregate labels, `UNMATCHED_<hex8>` vendors, agency key `"0"`, negative reversals.

**What is missing before it can be run.**
1. No audited statements are in the repo. The likely source is the Virginia Comptroller's Annual Comprehensive Financial Report (ACFR). **Owner:** supply the document and choose the first anchor figure.
2. A written mapping from the statement line to fund, agency and object. The APA files are a transaction extract and will not equal the statement exactly. The documented difference, itemised to named lines, is the experiment.
3. Revenue is not in Gold (the TTL revenue path exists but has no real-corpus run). Needed only if the anchor is net or reserves-based. An expenditure-only anchor can go first.
4. Allocation and currency adjustments have no real-corpus run (allocation is `partially_verified` on a smoke profile only). They are the intended long-term content of the "other" part and belong to a later test.

**Relation to D9.** D9 (net income) stays open. Reserves (revenue minus expenditure, cash or encumbrance basis, per fund) is one candidate target; this tie-out is another. Choose after the anchor figure is known.
